# Conformance with OSS_GAME_SPEC.md

[`OSS_GAME_SPEC.md`](../OSS_GAME_SPEC.md) at the repository root is this
project's governing specification, and the committed copy IS the spec — it is
self-contained, amended in a reviewed pull request, with no upstream document
to reconcile against and no validator to phone. This page is the other half of
that arrangement: **one row per chapter, a verdict, the evidence behind it,
and — where the repo falls short — what the gap costs and what closing it
would take.**

It exists because a conformance claim with nothing behind it is a badge. The
`sync-game-spec` skill walks the spec chapter by chapter and re-dates every
row; a sweep that changes no code still updates this file, because a verdict
with no date behind it is an opinion.

**Verdicts:** ✅ conformant · ◐ partial, with the gap named · ✗ not conformant
· — not applicable, with the reason.

_Last walked: 2026-09-09, against spec v1.1.0._

## What to do next, in the order it pays

The gaps are not equal. In descending order of value per hour:

1. **§23.7 — walk the import graph in a test.** A suite that reads the real
   imports and fails when `engine/` names three.js, Preact or `pwa/`, when a
   shell names another shell, or when anything imports `scripts/`. Forty
   lines, and it converts four "hard rules" in `AGENTS.md` from discipline
   into a gate. The spec calls it the single highest-value structural test a
   game repository has, and it is the cheapest item on this list.
2. **§36 — version and namespace the saves.** A version field per persisted
   structure, a read that fails visibly rather than silently, the key prefix
   moved into `identity.ts` (§35.6) and branched per deploy slot so the
   preview build stops eating production's high scores. This is the only gap
   on the page that can cost a player something they cannot get back.
3. **§12 — `--help` and an unknown-flag exit.** One shared argument parser in
   `scripts/lib/`, adopted by thirty tools. A measuring tool that ignores a
   typo reports a confident wrong number, and every lab on the labs table is a
   measuring tool.
4. **§32.2 / §32.5 — give the sim a verdict and the engine a stopwatch.** A
   pass/warn/fail line against stated targets, an `--against` flag that diffs
   two configurations in one run, and a steps-per-second benchmark with a
   recorded baseline.
5. **§20.3 / §23.8 — the rule/content split.** The largest of the cheap ones:
   a fixture registration seam the rule suite uses instead of shipped car ids.
   It is the same seam §27.1 would need, so price it with mods rather than
   alone.

Everything below that line — §24, §26, §27, §28, §39 — is a programme, not a
patch. Each is recorded here so that the next contributor to reach for one
finds the reasoning rather than re-deriving it, and so that a spec sweep stops
re-discovering the same six findings.
