# Architecture

The repository follows the shape of its sibling game repo: a headless engine that IS the game, a thin browser shell that draws it, and tooling that measures it. One direction of dependency:

```
tests/  scripts/(sim, previews)          pwa/ (Preact + three.js shell)
        \                                 /
         `----------->  engine/  <-------'
                 (framework-free TypeScript)
```

## `engine/` — the game, headless

The engine is a pure TypeScript module with no framework, no renderer, and no DOM. Its public surface is `engine/index.ts`:

- `createGame({ seed, carId })` builds a run: the compiled stage and a car on the grid.
- `step(state, input)` advances one fixed 120 Hz timestep and returns the `GameEvent[]` that step emitted (`takeoff`, `landing`, `splash`, `shift`, `respawn`, `finish`, …). The browser's render loop and the headless simulator call this same function — there is no other way to advance a run.

Determinism is a hard invariant: everything random draws from the seeded RNG in the state (`engine/lib/prng.ts`), never `Math.random`, so a seed fully reproduces a stage and a bot run — which is what the sim digests and shareable daily stages rely on.

Internally:

| Module          | Owns                                                                                                                                                                                                                                                                                                                              |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

| `game/defs/`    | Content as data: the car catalog, the global feel tuning                                                                                                                                                                                                                                                                          |
| `game/step.ts`  | Run orchestration: phases, progress, respawns, finish, event emission                                                                                                                                                                                                                                                             |
| `game/track.ts` | Car-to-track queries: progress fix, lateral offset, surfaces, lips                                                                                                                                                                                                                                                                |
| `mapgen/`       | The stage rules engine — see [track-generator.md](track-generator.md) — the terrain field (`terrain.ts`, the seeded driveable landscape around the road) and the prop field (`props.ts`, every solid thing standing on it plus the region/grove/stand quilt that decides where each belongs). Both shared by physics and renderer |

## `pwa/` — the browser shell

A Vite + Preact app that renders the engine and ships it as an installable PWA:

- `src/game/renderer.ts` — the three.js facade: builds a `World` per stage (road ribbon with start/finish dirt aprons, rumble strips, dirt skirts, fords, rally gates with hay bales), the car, dust particles, and the camera. It reads `GameState`; it never steps physics. A stage is not raised in one go: the road goes up a slice at a time and the ground a few tiles at a time, on the frames after it (`world.sync`), so changing a setting in Roam grows a new stage in instead of freezing the app while it is born. The world is lit by the environment's own hemisphere and sun (`environment.ts`, over `sky.ts` for the colours, `clouds.ts` for what is in the sky and `storm.ts` for the electrics) and vertex-colored with procedural speckle textures (`textures.ts`); the CAR is fullbright, its shading baked into vertex colors so the arcade look never pops, and the environment hands the renderer a tint that puts the failing light back on the paint. The rough arcade look is deliberate.
- **What a frame costs, and how it is kept down.** The renderer's budget is DRAW CALLS before it is triangles: a stage is thousands of separate things, and a car alone was forty of them before its wheels were welded into one mesh each. Four rules hold the count down, and `make profile` is how any change to them is judged. (1) _Nothing is built twice_ — every procedural texture, the flora library's shapes and the two materials it plants them with are made once and shared by the whole app (`lib/shared-gpu.ts` marks them, and every teardown path skips what is marked, because a chunk being dropped must not free what the chunks still standing are drawn with). (2) _Anything repeated is instanced_ — flora, stone litter, the crowd and the sky's clouds are all one draw per kind, not one per thing. (3) _Nothing rigid is split_ — a wheel is one geometry, not a tire plus a rim plus eight lugs, because nothing ever moves one of them relative to another. (4) _Nothing invisible is submitted_ — the camera's far plane stands well past where the fog goes solid, so `world.cull` hides the road chunks and wild cells past the fog's own far distance, and the clouds cull themselves cluster by cluster (they orbit a ring the camera stands inside, so three's own test over the whole ring always answers yes).
- `src/game/biome.ts` / `flora*.ts` — the nature: biomes as data and the parametric low-poly flora library (~40 tree/shrub/dead-wood/ground-cover variants, one instanced mesh per variant per patch of ground, wind-swayed grass and ferns). The library is split three ways — `flora-build.ts` (the primitives and the paint box), `flora-species.ts` (the roster of recipes) and `flora.ts` (shapes, materials and instancing). **The landscape is quilted at three scales**, all of them placed in the ENGINE (`mapgen/props.ts`) because the trunks are collided with: a SUB-REGION (~900 m) says what kind of country this is — dense forest, open taiga, a logging block, a bog, an old burn — and re-weights the GROVES (~150 m) below it, while a STAND noise (~42 m) clumps the trees inside one grove into closed thickets and the clearings between them — and inside that, a tree cell grows a CLUMP of one to four stems rather than a single trunk, at no cost in density, because a grid that holds one trunk per cell can only ever produce grid spacing. The same field lays BLOWDOWNS (parallel fallen trunks down the fall line where a gale went through) and ROCKY OUTCROPS (five to ten stones bedded into a steep hillside along its contour). `biome.ts` maps those ids to species mixes, ground cover and per-region ground colors; `planting.ts` decides which species dresses each engine trunk and each engine prop (fallen trunks, stumps, timber stacks), with the water and the altitude overriding the quilt — shoreline, stream bank, highland; it also grows the UNDERSTORY, the skirt of saplings, junipers and moss that low growth keeps around the foot of a mature trunk. Two callers decide where: `world.ts` for the band each road chunk carries (planted as a unit, so the fog cull can hide it as one), `wild.ts` for the open country beyond it (pooled into one instanced mesh per variant across every cell standing, because a cell holds too few of any one plant to be worth a draw call of its own). A variant's shape is BUILT ONCE and shared by every patch that plants it — a handful of jittered builds each, from a cache keyed by variant, jitter AND SEASON — so a stage streaming in uploads a few dozen geometries rather than one per variant per chunk. All of it seeded by the track seed. The `nature` skill owns the details.
- **The weather.** `RaceEnv.weather` is clear, rain or storm, and the last two are not the first one dimmed by different amounts — they are a LID on the sky. `sky.ts` turns the conditions into a `Preset`, and a wet one carries a `Deck`: a ceiling a few hundred metres up whose UNDERSIDE (`clouds.ts` draws it, one mesh, one draw) is most of what the player can see. The two wet skies then move in opposite directions, which is what stops both collapsing into grey. Under RAIN the deck is thin enough to glow — near white overhead, greying toward the rim where the line of sight runs the long way through it, so a rainy day is a WHITE sky. Under a STORM it is kilometres thick and sits in its own shadow — nearly black overhead, with the only daylight left in the strip that gets in UNDER the base at the horizon, which is the gust-front look. The fair-weather cumulus ring does not disappear under either: it drops below the base and becomes SCUD, flattened, darkened and tearing along at two and a half times the pace, which is the only place the wind under a cloud base is visible. How heavy a given stage's weather is comes from `weather.ts`: `coverOf` reads where the stage's own seeded wind sits inside the band its weather allows (`TUNING.wind.speed`), so no two wet stages get the same ceiling and the same seed always brings the same one back; `squallOf` reads the LIVE gust against that mean, so the sheet of rain thickens exactly as the car is shoved sideways — one gust, felt, seen and heard. A heavy deck also takes the daylight down far enough that the car turns its lights on at noon.

- **The storm.** `storm.ts` owns the lightning and is deliberately not a light that blinks on a timer. Strikes come in CELLS (the rate itself breathes, so the quiet stretches are what make the next crack land) with gaps drawn from an exponential; each strike has a DISTANCE, which decides how bright it is, whether a forked channel is drawn at all or only the cloud lighting up from inside (sheet lightning), and — the one nobody fakes — how long the sound takes to arrive, at 343 m/s. A flash is several RETURN STROKES tens of milliseconds apart rather than one smooth decay, and it lights the world FROM the bolt's bearing rather than lifting the key that is already there. Reduced motion keeps the storm and takes away the strobe. The thunder is a CUE, not a `GameEvent`: the simulation has no weather in it, so the renderer says when a clap arrives and how far it came, and `soundForThunder` in the audio router decides what that sounds like. Reviewed with `make sky`, which renders every weather against every time of day and waits for a near strike — a run screenshot can only ever show one sky, and a flash lasts a fifth of a second.

- **The seasons.** `RaceEnv.season` is spring, summer or autumn — the taiga has three, because the boreal forest under snow is a different biome (arctic) rather than a fourth season of this one. A season is not a filter: the year's colours are baked into the flora's vertices and the terrain's paint, so changing it re-plants the world (`renderer.setConditions` watches for it). What changes is what actually changes in a boreal forest — the broadleaves, the larch, the ground layer and the bogs — while every conifer, every bark and all the dead wood stay exactly where they are, which is what keeps the taiga's silhouette still while the colour moves. The LIGHT is derived rather than art-directed (`environment.ts`): at 62°N the noon sun stands 51° up at midsummer and 26° up at the September equinox, so the season scales the sun's elevation and the extra air mass its beam then travels through is charged against the Rayleigh optical depths of the three colour channels — which is why an autumn stage is warmer, dimmer and longer-shadowed before a single leaf has turned.
- `src/game/car-body.ts` + `src/game/car/` — the car generator. `car-body.ts` is the assembly line; the parts live beside it: `car/spec.ts` (the whole `CarBodySpec` vocabulary, pure types), `car/builder.ts` (the triangle accumulator that bakes a fixed fake sun into vertex colors, plus the patch helpers), `car/shell.ts` (the lofted chassis — wheel-arch openings cut into the flank, panel shut lines as V-grooves, and the geometry queries every other part asks of it), `car/greenhouse.ts` (windows cut out of a solid cabin, gutters, and the two SCREENS handed on as glass — the openings are REAL holes and the glass is a translucent mesh of its own, fading in colour and opacity from a baked pale sky at each pane's header to a clear, dark pane at its sill, which is how a fullbright game gets a reflection), `car/interior.ts` (what that glass is for: the cabin lining — the same panels drawn again from the inside with the same holes in them, without which the far flank is a culled back face and a window shows sky — plus the dash, seats, the crew sat in them, and at FULL detail a roll cage, harnesses and a steering wheel that turns with the front tyres. Everything is placed against the WINDOW SILL and the body's own top deck rather than against the floor: a 1.4 m car lofted from a profile has about 350 mm of cabin above that deck, and a crew stacked up at honest human proportions comes out entirely below the glass), `car/crew.ts` (the people, built parametrically from `car-crew.ts`'s roster: sixteen CARICATURES — the player, the campaign's fourteen crews and a privateer for anybody else — each a set of multipliers on a standard adult sat in a bucket seat, plus what is on the head and a signature set of gear colours (overalls, the stripe over the shoulders and the lid, the helmet shell). The differences are chosen for what survives a tinted pane at a car's length: width across the shoulders, head size, how far it clears them, and whether there is a full lid, an open one with a mop of hair out of it, a flat cap or a bouffant. The roof is a hard limit — a helmet is 290 mm across and a coupe's cabin is 260 mm deep — so every head is clamped under the headliner and tall hair is SQUASHED to whatever room is left rather than pushing the face below the window line. The MAP READER in the other seat is deliberately one model for the whole field, wearing the driver's own colours and holding the road book, because the pair has to read as one team. `make crew` renders them), `car/wipers.ts` (the grime that settles on those screens — water film in the rain, road-brown off a gravel stage — and the tandem pair and single rear arm that clear it: each blade only ever wipes the arc it actually sweeps, so the corners it never reaches stay dirty and a cleared band greys over again while the blade is away), `car/fascia.ts` (grille, wrap-around bumpers, air dam, detachable bonnet and boot lid, and where each lamp is placed), `car/lamps.ts` (the lamps themselves, which are the one part of a car that is LIT rather than painted, and are built and painted differently for both halves of that. Each is a BOWL standing proud of the cap it is bolted to — a housing, a reflector sloping back to a pan, dividers breaking the lens into cells, and the bulb's hot spot on each pan — because what reads as a lamp is the ring of shading around the hollow, not the colour, and a flat coloured plate reads as a sticker at every distance. It stands proud rather than sinking in because the cap is a solid face that would draw over a sunken pan, leaving a ring of reflector around a hole full of body paint. And every lit surface goes onto its own mesh with its own material, exempt from the environment tint the rest of the car takes as a multiply: a lamp is the one thing on a body that gets BRIGHTER as the light fails, so it is switched instead — full authored colour when lit, and no darker than a floor when not — with the additive bloom over each cluster (`car-mesh.ts`) as the light escaping it. Both halves are needed: the bloom alone is a smear, the bowl alone never lights up), `car/trim.ts` (arch extensions, mirrors, handles, mud flaps, livery bands, blocky door numbers, spoilers) and `car/wheels.ts` (three rim styles on a faceted tire, welded with the lugs into the single geometry all four corners share). `car-styles.ts` holds the per-car specs as pure data — no three.js — so Node tooling and the `--variants` loop can read them. `car-livery.ts` is the same kind of data one level up: a table of palettes crossed with paint PATTERNS (a swept crescent, a raked split with a comb of pinstripes, a belt-line two-tone, a chequer run, blocked wings…) and `applyLivery`, which repaints a spec into one of them — replacing what the spec painted while keeping what it bolted on, which is the distinction `SideBand.role` draws. It dresses the FIELD: `liveryFor(slot)` is deterministic, so a car you race looks the same every time, and the car the player drives is never repainted. On top of that sits `RIVAL_SCHEMES` — a palette and a pattern authored for each of the campaign's fourteen named crews (`engine/sim/rivals.ts`), because the colour is the only thing about a rival the player can learn at a glance and it should say something true about how that crew drives. Every crew has a colour nobody else has, and the door roundel carries their START NUMBER rather than a number out of a hat. `make liveries` renders one body in the schemes; `make field` renders the actual start list, each crew in their own car.

- `src/game/car-fx.ts` — every transient pool the car's contact with the world spawns into (gravel, mud, tyre smoke, the towed plume, water and foam, exhaust), plus the weather and the ambient life that share their budget, and the four-wheel burst a landing or a take-off is. It owns what the pools ARE and how the failing light tints them; the renderer keeps every decision about WHEN anything is thrown, because that needs the whole frame.
- `src/game/car-mesh.ts` — the scene wrapper: pitches the body to the road and the flight, spins and steers the wheels, and adds the jump-selling blob shadow. `car-damage.ts` bends the body's polygons from the engine's damage ledger and tumbles torn-off parts as debris; `car-dirt.ts` spatters a stage's worth of grime onto them, heaviest at the wheels that threw it. Iterate on looks with `make cars` (see the `car-design` skill).
- `src/game/ghost.ts` — the time trial's ghost, kept as the CONTROLS the run was driven on rather than as a path. The engine is deterministic, so replaying a recorded input tape through a second `GameState` on the same compiled track reproduces the run exactly — every drift, jump and dent — for a few tens of kilobytes a stage (run-length coded, one localStorage key per level). The bargain that buys it is that `input.ts` snaps the wheel and the pedals onto that tape's grid before the engine sees them, so what is written down is what was driven. Nothing connects the two games, which is why the two cars cannot touch.
- `src/game/standings.ts` — R29, the campaign's field. It builds fourteen more `GameState`s on the same compiled track as the player's run and steps them beside it, each driven by the real bot on its own skill profile (`engine/sim/rivals.ts`) in its own car. There is no table of authored times and no par curve: the rivals brake for the corners the player brakes for and lose the seconds anybody loses, so the field cannot drift away from the handling. The track is shared and read-only, so fourteen rivals cost fourteen cars and not fourteen worlds — about 11 MB and a percent of a frame on the longest stage in the game. The STAGGER is real rather than a story told over a simultaneous start: car 1 leaves thirteen intervals before the player and car 14 exactly one, on the first frame of the establishing shot, so the crew in front is something the player WATCHES leave. Thirteen intervals of driving is about a second of CPU, so it is paid off in budgeted slices under that shot, and a crew still owing time has not left the control — nothing draws it and nothing can hit it, which is what lets the whole field be entered on one staging slot. That slot is not the player's: the field is stood `GRID_STAGGER` metres to their right, so the crew in front pulls away from ALONGSIDE the player rather than out of their bodywork. They ARE drawn now (`src/game/field-cars.ts`, built lazily as a crew comes within reach and switched off past draw range) and they are SOLID (`collideCars`): catch the car in front and you can lean on it, or put it off the road. Each of them is also NAMED while it is close enough to matter (`src/game/name-tag.ts`): a plate over the roof carrying the crew's alias and the start number off their own door, in their car's own colour, so the car you are about to lean on is Frostbite rather than a blue coupe. The tag is a label, a colour and a point in the world and knows nothing about rivals — the time trial hangs the same plate on the ghost, and whatever puts other people's cars on the road next hands it the same three things. It holds a constant height on screen (`sizeAttenuation: false`, so the scale it is given is an angle), and it is DEPTH-TESTED like everything else in the world rather than drawn over it: a stagger spreads the field over hundreds of metres of a road that bends through a forest, so a plate that ignored the depth buffer would name three crews in a frame with no cars in it. It also lives on a layer of its own, because the rear-view mirror reverses its own image and a reversed word is not a name. HUD option: NAME TAGS. Rivals never resolve against each other — what a rival's time means is a stage they drove alone, and the player is the only disruption. Because everybody ahead really is ahead, a place at a split board is an exact count of the better times rather than a provisional one. Past the line it also RUNS THE STRAGGLERS HOME: the crews still out there are stepped to their finish off the results card's frames, a bounded slice at a time, because R30's points go to a finishing order and the two places behind the player are worth something to somebody — anybody still going at a limit is retired where they stand, so a bot wedged against a trunk cannot hold the card open. It also enters the OTHER kind of start: a HEADS-UP race hands `createField` a `FieldPlan` — how good the field is, how many cars are on it, and whether they leave together — and a MASS START stands them on a zig-zag grid on the apron behind the start gate (`engine/sim/grid.ts`) instead of in a queue, owing nobody a head start, sitting through the same lights the player does, and driving through the gate together on the green. The player takes the last slot, and the metres that costs come back as the game's only catch-up. The same module keeps the DERIVED start list the time trial and Roam still need, where nobody is entered and R25's finish salute still has to be sized by something.
- `src/game/campaign.ts` + `results-table.tsx` — R29/R30, the campaign, which IS its championship. The module holds the authored stages (a seed, a length band, a shape and conditions per level, so the same rules engine builds them for everybody) AND the points they are played for, in ONE localStorage record: every campaign stage pays 3/2/1 to its podium — the player and the fourteen rivals alike, off the classification `standings.ts` builds once the last car is home — and a location's table is those stages added up. There is no second board on top of it. The points ARE the locks: a stage opens once the one before it paid the player something (which is to say a podium), and a country opens once the one before it has been driven all the way through with the player top of its table (`locationWon`, which is what stops an all-square empty table from opening a country nobody has raced for). Nothing is ever spent: a stage can be re-run as often as the player likes for a better place, time and points, and the board keeps whichever afternoon paid them more, so a lap for fun can never cost a title. The player's own place is booked AT THE LINE (`recordFinish`) so pressing straight on to the next stage cannot lose the stage just won, and the field's places fill in behind it when the stragglers are home (`recordResult`). A save from the version that kept a separate `scandi-flick-championship` season is folded into the one record on read, and the old key is retired on the next write. `results-table.tsx` draws the sheet in the two places it is asked for: the modal the results card opens (place, crew, time, stage points, location total) and the campaign menu's own standings.
- `src/game/main-menu.tsx` + `menu-levels.tsx` + `menu-headsup.tsx` + `menu-car.tsx` + `car-stats.ts` — the menu's pages and the PRE-RACE CARD between them and the road. `menu-levels.tsx` holds the STAGE GRID the three stage pages share — campaign, time trial and heads up show the same boxes behind three different gates, so the gate is passed in and nothing else about a stage box is a page's business; `menu-headsup.tsx` is the third of those pages, with the mode's three settings (rivals, mass start, cars) under the grid. Picking a stage on either grid does not start it: it opens the card, where the car turns on its stand beside its spec sheet and the transmission is chosen, and START is the only thing that begins a run. A road and a car are two decisions, and the car picker was invisible as a row under six stage boxes. The sheet itself is DERIVED — `car-stats.ts` reads the catalog (`engine/game/defs/cars.ts`) for every figure and every bar, so a car retuned there bills itself correctly with no second table to update, and the bars are scaled across the ROSTER rather than from zero because what the player is choosing between is three cars, not three absolutes.
- `src/game/scores.ts` + `score-board.tsx` + `hud-initials.tsx` — the time trial's high score table: ten rows a stage, three letters each, one localStorage key per stage plus one for the name last entered. Deliberately not the same thing as the campaign's `best` time (`campaign.ts`), which is what the HUD's target clock and the ghost read and which has no business knowing who was driving. The entry is the arcade's: the slots come up holding the remembered name, the first key typed replaces it from the first letter, and the chevrons are the control on a phone.
- `src/game/mirror.ts` — the rear-view mirror: a second pass over the same scene from a camera bolted to the CAR looking back, composited as a strip of glass at the top of the frame. It is deliberately independent of the camera mode — bonnet or helicopter, the strip answers the same question — and the image is flipped left-for-right, which is why it goes through a render target rather than a scissored viewport: negating the projection's x would reverse every triangle's winding. It sees a fraction of the forward view's distance with the fog pulled in to match (`environment.withHaze`), so the world leaves its frustum where the air had already gone solid rather than being cut off in mid-view. The bottom edge it works out to is restated in `styles.css`, which is what the co-driver's calls hang under. The picture has TWO homes, which is why the pass is split into a `fill` and a `composite`: from the COCKPIT it is drawn into the mirror hanging in the windscreen (`car/cockpit.ts`) instead of onto the strip, so the rear view swings with the body on its springs and slides across the frame as the driver's head is thrown about — and the fill therefore runs BEFORE the frame rather than after it, because geometry can only sample a texture that already exists. A player option, and the most expensive one: it roughly doubles the driving frame's draw calls before the range is pulled in.

- `src/game/camera.ts` — camera **modes**. Eight can be driven from and are one ladder from behind the wheel outwards (`cockpit`, `hood`, `bumper`, `close`, `chase`, `far`, `heli`, `top`); `drone` and `map` are placed by the app for the menu backdrop and the Roam page. The five outside ones are the same rig with different proportions — one table of numbers, one update function — so an angle is a row rather than another camera. They track a blend of nose and travel direction so drift angle reads on screen. What makes `close`, `chase` and `far` one shot at three lengths is the LOOK-OVER ANGLE — the depression from the lens to the top of the car's own roof, held at about 13° by all three — because that angle, not the height, is what decides whether the player can see where they are going: it sets how far up the frame the roofline reaches and how much road is left above it. Height is therefore a consequence of the standoff rather than a free number, and a camera parked at roof height, however short the boom, is a camera looking at a roof. `close` and `chase` — the two the game is actually driven from — also carry identical steadying numbers and differ only in where they stand, because a longer boom that also answers more slowly turns the same yaw lag into more metres of world sloshing across the frame; the weight that makes a camera read as FLOWN starts at `far`, whose lateral swing is a sprung mass that overshoots a turn and settles back. The ground they may never sink under is read over the camera's own footprint and only ever sinks at a bounded rate, so a step in the terrain is flown down rather than cut to; and over a CLIFF they hold part of the height they had at the top and let the car fall away below them, keyed to how far it has dropped under where it left the ground so a designed jump never triggers it. They hang off the car's height on a little PLAY rather than on the height itself, because the road has a cross-section (R16) and the car rides it: absorbing a wheel track, the crown and the step onto the verge is what stops a corner heaving the whole picture on a stage that is dead flat, while anything bigger than the play — a crest, a landing, a cliff — still moves the shot one for one. `map` frames a whole stage from the sky and takes the Roam page's drags, wheels and pinches (turn, tilt, zoom); it also solves its own near and far planes, because a driving near plane under a kilometres-away far one leaves the depth buffer metres of resolution and every lakeshore shimmers. What it frames is cut to an island (`map-island.ts`).
- `src/game/camera-eye.ts` — the three cameras taken from INSIDE the car, as one rig with a head on it: `cockpit` behind the wheel, `hood` on the car's own scuttle over its bonnet, `bumper` down at the nose ahead of every panel. What separates them from the chase rigs is that a lens bolted to a bodyshell is a still photograph — the stage's ground is a smooth loft, so on a straight it does not move at all. Two things put the motion back. The EYE HAS MASS: it rides a neck, a damped spring chasing the mount, so it plunges and rebounds into a rut, is thrown forward under the brakes and sideways through a corner, and settles a beat after the car does; the spring damps head-against-seat, never head-against-world, or the head would trail metres behind the car at pace. And the ROAD HAS GRAIN: a three-oscillator vibration applied as MOTION rather than shaken into the spring, because a mass on a spring at ~2 Hz answers a 10 Hz road with almost nothing. Its top oscillator is capped by the SLOWEST frame rate the game is played at rather than by how fine a buzz would be nice — past what a frame can draw as a wave it stops describing the road and starts describing the sampling — and the neck saturates into the end of its travel instead of being clamped to it, so a landing never stops the head dead inside one frame. A HIT throws the head along the direction the blow came from and rings a small rotational wobble on top, which from inside the car is the only thing in frame that says anything was struck. The body's roll reaches the horizon through the same PLAY the chase rigs stand on, separated by TIME rather than size: a bank is held for a corner and a wheel track is crossed in a second. Four of its numbers belong to the player (OPTIONS ▸ VIEW): seat height, seat reach, field of view, and how much head motion there is at all — the last winds the neck, the grain, the jolt and the wobble down together, to nothing.
- `src/game/car/cockpit.ts` — the first-person cabin, built ONCE for the player's car where `car/interior.ts` is built fifteen times for the field: a fascia with a face, a binnacle with two lit dials whose needles move, a full-size wheel on a column, pedals, cage bars up the screen pillars, a sun strip and a rear-view mirror hanging in the top of the windscreen with the mirror pass's own picture in it. It only fits because the body's top deck is CUT AWAY under the cabin for a car that will be sat in (`OpenCabin` in `car/shell.ts`): the loft is a closed body, so out of the box the cabin is a tray 350 mm deep between that deck and the roof, and a seated driver and a 320 mm wheel do not fit in 350 mm. Cutting it makes the room a metre deep and makes this file responsible for closing it again — a floor at footwell height, an inner sill each side and a bulkhead at each end — while `car/interior.ts`'s own pan closes it in every view the cockpit is not up in. Three materials, and each split buys something: the cabin is darker than the paint outside it and goes to almost nothing at night, the two instruments answer to nothing the sky does, and the sun strip is translucent.
- `src/game/input.ts` / `gamepad.ts` / `hud.tsx` / `hud-touch.tsx` — keyboard, touch and controller, and the arcade HUD. A pad fires no events, so `input.ts` polls every connected one once a frame and `gamepad.ts` — DOM-free, reading plain snapshots so the tests can hold a pad still — turns the sticks, the analogue triggers and the buttons into the same axis, pedals and presses the other two surfaces produce. The thumb zones themselves are `hud-touch.tsx`, split off the HUD because they are the one surface that does not run off the snapshot — they write into the input manager at pointer rate — over three DOM-free policy modules the tests can read: `thumb-guard.ts` (every way a grip on a finger has to be able to END), `pedal-gesture.ts` (what a drag MEANS, and the timing that separates a gear flick from the brake bound to the same direction) and `shift-window.ts` (which gears a flick may take: a key or a pad shoulder is a deliberate press and shifts whenever asked, a thumb is held to gears the revs will hold). A connected pad takes the thumb zones off the screen, and `menu-nav.ts` (over the DOM-free `menu-cursor.ts`) lets it walk the menus — generically, off the buttons already on screen, so a page added tomorrow is navigable the day it is written. Together that is what makes an installed PWA on an Android handheld playable end to end with the controls it already has. `minimap.tsx` builds the top-right map from the compiled track and draws it: the route, the car's arrowhead, and the run's progress as a gauge on the frame's own border; tapping it opens the in-race pause card (`menu.tsx`, which also holds the option vocabulary every menu surface shares). The HUD re-renders from a ~12 Hz snapshot (`snapshot.ts`), which is fine for every instrument except two: the race clock, whose hundredths digit is the point of it, and the start lights, which have to change on the same frame as the tick that goes with them. Those two live in `hud-clock.tsx` and read a `LiveRun` the frame loop rewrites in place — the clock writes its digits straight into the DOM, so sixty updates a second cost two text nodes rather than a re-render of every dial.
- `src/lib/synth.ts` / `src/lib/tracker.ts` / `src/game/audio/` — the sound. A small WebAudio synth (the only module in the tree that touches an `AudioContext`), a tracker sequencer, the sound bank as data, the event router, and the continuous road bed the engine/tyres/wind/drift are made of. Nothing is a file: every effect and every note is synthesized from parameters — see [audio.md](audio.md), and hear it with `make audition`.
- `src/game/screenshots.ts` + `shot-plan.ts` + `menu-gallery.tsx` — the camera the player carries. ENTER (or the shutter on the HUD's button row, which is how a phone reaches it) leaves a REQUEST behind and the frame loop serves it: the renderer runs with no `preserveDrawingBuffer`, so the pixels have to be lifted off the drawing buffer inside the same animation callback that drew them, and everything that can wait — the mark stamped into the corner, the PNG encode, the write into the roll — happens after. The picture is the rendered frame and not the HUD over it: rasterizing a live stylesheet is a different piece of machinery, and what a rally screenshot is about is the car sideways in the trees. What is DECIDED about a picture (its size, its name, where the mark goes) is split into `shot-plan.ts`, which is DOM-free so the tests can hold it to a promise; the mark itself is read from the same `icons/icon.svg` the raster icons are generated from, inlined at build time so an offline picture is signed like any other. The roll is `lib/shot-store.ts` — IndexedDB, because a PNG is not a few kilobytes of JSON and localStorage's whole budget is 5 MB — over the pure policy in `lib/shot-roll.ts` (newest first, capped at forty, oldest out). It is never load-bearing: a private-mode tab with no IndexedDB at all keeps the roll in memory and loses nothing but the pictures at the end of the session. `menu-gallery.tsx` is the viewer — one shot fills the page, the roll is a filmstrip under it — and `lib/share-image.ts` answers the only question the buttons have, which is what THIS browser can do with a PNG: the platform's share sheet, the clipboard, or a download, each offered only where a real probe says it will work. A player option (OPTIONS ▸ CONTROLS), on by default.
- `src/App.tsx` — the fixed-timestep loop (engine at 120 Hz regardless of frame rate), the daily-seed stage rotation, car swap, and the new-build card (`game/update-card.tsx`, fed by the framework's `usePwaUpdate`).
- `pwa-plugin.ts` — hand-rolled service worker + manifest emission per deploy slot (the same pattern as the sibling contacts app); `src/app-pwa.ts` holds the cache-id contract both sides share.
- `src/identity.ts` — the single source for name, copy, palette, and URLs.
- `src/output-bridge.ts` — routes the engine's output module into the oss-framework log store.

The [oss-framework](https://github.com/niclaslindstedt/oss-framework) supplies the update-prompt state machine and UI (`pwa`), logging (`logging`), and the theme tokens its components style with; the runtime is Preact via `preact/compat` overrides.

## `tests/` and `scripts/`

Root-level vitest suites cover the generator's R-rules, the drift and jump moment by moment, the gearboxes, and full bot simulations (see [simulation.md](simulation.md)). `scripts/` holds Node tooling: the sim CLI, track previews, the audio audition page, headless screenshots, the icon/OG generator (pure-Node PNG encoder in `scripts/lib/png.mjs` — no native image deps), the SEO checker, and the release plumbing (`scripts/release/`, changeset fragments → CHANGELOG).

Several of those tools are the same shape and worth knowing as one: a
harness PAGE under `pwa/src/tools/` with its own HTML entry at the `pwa/`
root, and a `scripts/*.mjs` that builds just that entry, serves it, drives
it in headless Chromium and writes a sheet to `previews/`. `make cars`,
`make sky` and `make items` are all built this way, so the picture that
comes back is drawn by the modules the game ships rather than by the tool.
`make items` is the odd one in what it photographs: a single OBJECT — a
stone, a plant, a kerb post, the cabin behind a car's glass — on a fitted
turntable over a metre grid, which is the only place most of the world's
vocabulary is ever legible.

## Deployment

The app deploys to GitHub Pages at [game2.niclaslindstedt.se](https://game2.niclaslindstedt.se/) in three slots — `/` (latest release tag), `/preview/` (main), `/branch/` (parked feature branch) — via `pages.yml`; `release.yml` cuts versions from changeset fragments and chains the deploy. Details in [configuration.md](configuration.md); platform shells beyond the web in [platforms.md](platforms.md).
