# Architecture

The repository follows the shape of its sibling game repo: a headless engine that IS the game, a thin browser shell that draws it, and tooling that measures it. One direction of dependency:

```
tests/  scripts/(sim, previews)          pwa/ (Preact + three.js shell)
        \                                 /
         `----------->  engine/  <-------'
                 (framework-free TypeScript)
```

## `engine/` — the game, headless

The engine is a pure TypeScript module with no framework, no renderer, and no DOM. Its public surface is `engine/index.ts`:

- `createGame({ seed, carId })` builds a run: the compiled stage and a car on the grid.
- `step(state, input)` advances one fixed 120 Hz timestep and returns the `GameEvent[]` that step emitted (`takeoff`, `landing`, `splash`, `shift`, `respawn`, `finish`, …). The browser's render loop and the headless simulator call this same function — there is no other way to advance a run.

Determinism is a hard invariant: everything random draws from the seeded RNG in the state (`engine/lib/prng.ts`), never `Math.random`, so a seed fully reproduces a stage and a bot run — which is what the sim digests and shareable daily stages rely on.

Internally:

| Module          | Owns                                                                                                                                                                                                                                                                                                                              |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `game/car.ts`   | The handling model: grounded + airborne steps, the grip-and-slide model, gearboxes                                                                                                                                                                                                                                                |
| `game/defs/`    | Content as data: the car catalog, the global feel tuning                                                                                                                                                                                                                                                                          |
| `game/step.ts`  | Run orchestration: phases, progress, respawns, finish, event emission                                                                                                                                                                                                                                                             |
| `game/track.ts` | Car-to-track queries: progress fix, lateral offset, surfaces, lips                                                                                                                                                                                                                                                                |
| `mapgen/`       | The stage rules engine — see [track-generator.md](track-generator.md) — the terrain field (`terrain.ts`, the seeded driveable landscape around the road) and the prop field (`props.ts`, every solid thing standing on it plus the region/grove/stand quilt that decides where each belongs). Both shared by physics and renderer |
| `sim/`          | The bot driver and headless simulator — see [simulation.md](simulation.md)                                                                                                                                                                                                                                                        |
| `output.ts`     | The §19.4 central output module (semantic `status/info/warn/error/header/debug` with a pluggable sink)                                                                                                                                                                                                                            |
| `version.ts`    | The engine version constant (rewritten by `scripts/update-versions.sh`)                                                                                                                                                                                                                                                           |

## `pwa/` — the browser shell

A Vite + Preact app that renders the engine and ships it as an installable PWA:

- `src/game/renderer.ts` — the three.js facade: builds a `World` per stage (road ribbon with start/finish dirt aprons, rumble strips, dirt skirts, fords, rally gates with hay bales), the car, dust particles, and the camera. It reads `GameState`; it never steps physics. A stage is not raised in one go: the road goes up a slice at a time and the ground a few tiles at a time, on the frames after it (`world.sync`), so changing a setting in Roam grows a new stage in instead of freezing the app while it is born. The world is lit by the environment's own hemisphere and sun (`environment.ts`, over `sky.ts` for the colours, `clouds.ts` for what is in the sky and `storm.ts` for the electrics) and vertex-colored with procedural speckle textures (`textures.ts`); the CAR is fullbright, its shading baked into vertex colors so the arcade look never pops, and the environment hands the renderer a tint that puts the failing light back on the paint. The rough arcade look is deliberate.
- **What a frame costs, and how it is kept down.** The renderer's budget is DRAW CALLS before it is triangles: a stage is thousands of separate things, and a car alone was forty of them before its wheels were welded into one mesh each. Four rules hold the count down, and `make profile` is how any change to them is judged. (1) _Nothing is built twice_ — every procedural texture, the flora library's shapes and the two materials it plants them with are made once and shared by the whole app (`lib/shared-gpu.ts` marks them, and every teardown path skips what is marked, because a chunk being dropped must not free what the chunks still standing are drawn with). (2) _Anything repeated is instanced_ — flora, stone litter, the crowd and the sky's clouds are all one draw per kind, not one per thing. (3) _Nothing rigid is split_ — a wheel is one geometry, not a tire plus a rim plus eight lugs, because nothing ever moves one of them relative to another. (4) _Nothing invisible is submitted_ — the camera's far plane stands well past where the fog goes solid, so `world.cull` hides the road chunks and wild cells past the fog's own far distance, and the clouds cull themselves cluster by cluster (they orbit a ring the camera stands inside, so three's own test over the whole ring always answers yes).
- `src/game/biome.ts` / `flora*.ts` — the nature: biomes as data and the parametric low-poly flora library (~40 tree/shrub/dead-wood/ground-cover variants, one instanced mesh per variant per patch of ground, wind-swayed grass and ferns). The library is split three ways — `flora-build.ts` (the primitives and the paint box), `flora-species.ts` (the roster of recipes) and `flora.ts` (shapes, materials and instancing). **The landscape is quilted at three scales**, all of them placed in the ENGINE (`mapgen/props.ts`) because the trunks are collided with: a SUB-REGION (~900 m) says what kind of country this is — dense forest, open taiga, a logging block, a bog, an old burn — and re-weights the GROVES (~150 m) below it, while a STAND noise (~42 m) clumps the trees inside one grove into closed thickets and the clearings between them. `biome.ts` maps those ids to species mixes, ground cover and per-region ground colors; `planting.ts` decides which species dresses each engine trunk and each engine prop (fallen trunks, stumps, timber stacks), with the water and the altitude overriding the quilt — shoreline, stream bank, highland. Two callers decide where: `world.ts` for the band each road chunk carries (planted as a unit, so the fog cull can hide it as one), `wild.ts` for the open country beyond it (pooled into one instanced mesh per variant across every cell standing, because a cell holds too few of any one plant to be worth a draw call of its own). A variant's shape is BUILT ONCE and shared by every patch that plants it — a handful of jittered builds each, from a cache keyed by variant, jitter AND SEASON — so a stage streaming in uploads a few dozen geometries rather than one per variant per chunk. All of it seeded by the track seed. The `nature` skill owns the details.
- **The weather.** `RaceEnv.weather` is clear, rain or storm, and the last two are not the first one dimmed by different amounts — they are a LID on the sky. `sky.ts` turns the conditions into a `Preset`, and a wet one carries a `Deck`: a ceiling a few hundred metres up whose UNDERSIDE (`clouds.ts` draws it, one mesh, one draw) is most of what the player can see. The two wet skies then move in opposite directions, which is what stops both collapsing into grey. Under RAIN the deck is thin enough to glow — near white overhead, greying toward the rim where the line of sight runs the long way through it, so a rainy day is a WHITE sky. Under a STORM it is kilometres thick and sits in its own shadow — nearly black overhead, with the only daylight left in the strip that gets in UNDER the base at the horizon, which is the gust-front look. The fair-weather cumulus ring does not disappear under either: it drops below the base and becomes SCUD, flattened, darkened and tearing along at two and a half times the pace, which is the only place the wind under a cloud base is visible. How heavy a given stage's weather is comes from `weather.ts`: `coverOf` reads where the stage's own seeded wind sits inside the band its weather allows (`TUNING.wind.speed`), so no two wet stages get the same ceiling and the same seed always brings the same one back; `squallOf` reads the LIVE gust against that mean, so the sheet of rain thickens exactly as the car is shoved sideways — one gust, felt, seen and heard. A heavy deck also takes the daylight down far enough that the car turns its lights on at noon.

- **The storm.** `storm.ts` owns the lightning and is deliberately not a light that blinks on a timer. Strikes come in CELLS (the rate itself breathes, so the quiet stretches are what make the next crack land) with gaps drawn from an exponential; each strike has a DISTANCE, which decides how bright it is, whether a forked channel is drawn at all or only the cloud lighting up from inside (sheet lightning), and — the one nobody fakes — how long the sound takes to arrive, at 343 m/s. A flash is several RETURN STROKES tens of milliseconds apart rather than one smooth decay, and it lights the world FROM the bolt's bearing rather than lifting the key that is already there. Reduced motion keeps the storm and takes away the strobe. The thunder is a CUE, not a `GameEvent`: the simulation has no weather in it, so the renderer says when a clap arrives and how far it came, and `soundForThunder` in the audio router decides what that sounds like. Reviewed with `make sky`, which renders every weather against every time of day and waits for a near strike — a run screenshot can only ever show one sky, and a flash lasts a fifth of a second.

- **The seasons.** `RaceEnv.season` is spring, summer or autumn — the taiga has three, because the boreal forest under snow is a different biome (arctic) rather than a fourth season of this one. A season is not a filter: the year's colours are baked into the flora's vertices and the terrain's paint, so changing it re-plants the world (`renderer.setConditions` watches for it). What changes is what actually changes in a boreal forest — the broadleaves, the larch, the ground layer and the bogs — while every conifer, every bark and all the dead wood stay exactly where they are, which is what keeps the taiga's silhouette still while the colour moves. The LIGHT is derived rather than art-directed (`environment.ts`): at 62°N the noon sun stands 51° up at midsummer and 26° up at the September equinox, so the season scales the sun's elevation and the extra air mass its beam then travels through is charged against the Rayleigh optical depths of the three colour channels — which is why an autumn stage is warmer, dimmer and longer-shadowed before a single leaf has turned.
- `src/game/car-body.ts` + `src/game/car/` — the car generator. `car-body.ts` is the assembly line; the parts live beside it: `car/spec.ts` (the whole `CarBodySpec` vocabulary, pure types), `car/builder.ts` (the triangle accumulator that bakes a fixed fake sun into vertex colors, plus the patch helpers), `car/shell.ts` (the lofted chassis — wheel-arch openings cut into the flank, panel shut lines as V-grooves, and the geometry queries every other part asks of it), `car/greenhouse.ts` (windows cut out of a solid cabin, gutters, wipers), `car/fascia.ts` (grille, lamps, wrap-around bumpers, air dam, detachable bonnet and boot lid), `car/trim.ts` (arch extensions, mirrors, handles, mud flaps, livery bands, blocky door numbers, spoilers) and `car/wheels.ts` (three rim styles on a faceted tire, welded with the lugs into the single geometry all four corners share). `car-styles.ts` holds the per-car specs as pure data — no three.js — so Node tooling and the `--variants` loop can read them. `car-livery.ts` is the same kind of data one level up: a table of palettes crossed with paint PATTERNS (a swept crescent, a raked split with a comb of pinstripes, a belt-line two-tone, a chequer run, blocked wings…) and `applyLivery`, which repaints a spec into one of them — replacing what the spec painted while keeping what it bolted on, which is the distinction `SideBand.role` draws. It dresses the FIELD: `liveryFor(slot)` is deterministic, so a car you race looks the same every time, and the car the player drives is never repainted. On top of that sits `RIVAL_SCHEMES` — a palette and a pattern authored for each of the campaign's fourteen named crews (`engine/sim/rivals.ts`), because the colour is the only thing about a rival the player can learn at a glance and it should say something true about how that crew drives. Every crew has a colour nobody else has, and the door roundel carries their START NUMBER rather than a number out of a hat. `make liveries` renders one body in the schemes; `make field` renders the actual start list, each crew in their own car.

- `src/game/car-fx.ts` — every transient pool the car's contact with the world spawns into (gravel, mud, tyre smoke, the towed plume, water and foam, exhaust), plus the weather and the ambient life that share their budget, and the four-wheel burst a landing or a take-off is. It owns what the pools ARE and how the failing light tints them; the renderer keeps every decision about WHEN anything is thrown, because that needs the whole frame.
- `src/game/car-mesh.ts` — the scene wrapper: pitches the body to the road and the flight, spins and steers the wheels, and adds the jump-selling blob shadow. `car-damage.ts` bends the body's polygons from the engine's damage ledger and tumbles torn-off parts as debris; `car-dirt.ts` spatters a stage's worth of grime onto them, heaviest at the wheels that threw it. Iterate on looks with `make cars` (see the `car-design` skill).
- `src/game/ghost.ts` — the time trial's ghost, kept as the CONTROLS the run was driven on rather than as a path. The engine is deterministic, so replaying a recorded input tape through a second `GameState` on the same compiled track reproduces the run exactly — every drift, jump and dent — for a few tens of kilobytes a stage (run-length coded, one localStorage key per level). The bargain that buys it is that `input.ts` snaps the wheel and the pedals onto that tape's grid before the engine sees them, so what is written down is what was driven. Nothing connects the two games, which is why the two cars cannot touch.
- `src/game/standings.ts` — R29, the campaign's field. It builds fourteen more `GameState`s on the same compiled track as the player's run and steps them beside it, each driven by the real bot on its own skill profile (`engine/sim/rivals.ts`) in its own car. There is no table of authored times and no par curve: the rivals brake for the corners the player brakes for and lose the seconds anybody loses, so the field cannot drift away from the handling. The track is shared and read-only, so fourteen rivals cost fourteen cars and not fourteen worlds — about 11 MB and a percent of a frame on the longest stage in the game. Nobody DRAWS them: with ten seconds between cars there is nothing on the road to see, exactly as there is nothing to see in a rally, and what the player gets is the position board. The player is the last car out, so their place at a split board is simply every car already through it plus one — no time comparison, and nothing to interpolate between boards. The same module keeps the DERIVED start list the time trial and Roam still need, where nobody is entered and R25's finish salute still has to be sized by something.
- `src/game/scores.ts` + `score-board.tsx` + `hud-initials.tsx` — the time trial's high score table: ten rows a stage, three letters each, one localStorage key per stage plus one for the name last entered. Deliberately not the same thing as the campaign's `best` time (`campaign.ts`), which is what the HUD's target clock and the ghost read and which has no business knowing who was driving. The entry is the arcade's: the slots come up holding the remembered name, the first key typed replaces it from the first letter, and the chevrons are the control on a phone.
- `src/game/mirror.ts` — the rear-view mirror: a second pass over the same scene from a camera bolted to the CAR looking back, composited as a strip of glass at the top of the frame. It is deliberately independent of the camera mode — hood or helicopter, the strip answers the same question — and the image is flipped left-for-right, which is why it goes through a render target rather than a scissored viewport: negating the projection's x would reverse every triangle's winding. It sees a fraction of the forward view's distance with the fog pulled in to match (`environment.withHaze`), so the world leaves its frustum where the air had already gone solid rather than being cut off in mid-view. The bottom edge it works out to is restated in `styles.css`, which is what the co-driver's calls hang under. A player option, and the most expensive one: it roughly doubles the driving frame's draw calls before the range is pulled in.

- `src/game/camera.ts` — camera **modes**. Six can be driven from and are one ladder from inside the car outwards (`hood`, `close`, `chase`, `far`, `heli`, `top`); `drone` and `map` are placed by the app for the menu backdrop and the Roam page. The five outside ones are the same rig with different proportions — one table of numbers, one update function — so an angle is a row rather than another camera. They track a blend of nose and travel direction so drift angle reads on screen, and the distant ones carry weight: their lateral swing is a sprung mass that overshoots a turn and settles back. The ground they may never sink under is read over the camera's own footprint and only ever sinks at a bounded rate, so a step in the terrain is flown down rather than cut to; and over a CLIFF they hold part of the height they had at the top and let the car fall away below them, keyed to how far it has dropped under where it left the ground so a designed jump never triggers it. `hood` is the exception: it sits on the car's own scuttle (the mount is read off that car's silhouette in `car-styles.ts`, so the bonnet fills the bottom of the frame) and the eye is a driver's HEAD — a damped spring chasing the mount, thrown forward under the brakes and sideways through a corner, plunging and rebounding through a landing, with the road's grain shaken through it and a glance into the slide. `map` frames a whole stage from the sky and takes the Roam page's drags, wheels and pinches (turn, tilt, zoom); it also solves its own near and far planes, because a driving near plane under a kilometres-away far one leaves the depth buffer metres of resolution and every lakeshore shimmers. What it frames is cut to an island (`map-island.ts`).
- `src/game/input.ts` / `hud.tsx` — keyboard + touch, and the arcade HUD (also the touch control surface). `minimap.tsx` builds the top-right map from the compiled track and draws it: the route, the car's arrowhead, and the run's progress as a gauge on the frame's own border; tapping it opens the in-race menu (`menu.tsx`, which also holds the pre-race card). The HUD re-renders from a ~12 Hz snapshot (`snapshot.ts`), which is fine for every instrument except two: the race clock, whose hundredths digit is the point of it, and the start lights, which have to change on the same frame as the tick that goes with them. Those two live in `hud-clock.tsx` and read a `LiveRun` the frame loop rewrites in place — the clock writes its digits straight into the DOM, so sixty updates a second cost two text nodes rather than a re-render of every dial.
- `src/lib/synth.ts` / `src/lib/tracker.ts` / `src/game/audio/` — the sound. A small WebAudio synth (the only module in the tree that touches an `AudioContext`), a tracker sequencer, the sound bank as data, the event router, and the continuous road bed the engine/tyres/wind/drift are made of. Nothing is a file: every effect and every note is synthesized from parameters — see [audio.md](audio.md), and hear it with `make audition`.
- `src/App.tsx` — the fixed-timestep loop (engine at 120 Hz regardless of frame rate), the daily-seed stage rotation, car swap, and the new-build card (`game/update-card.tsx`, fed by the framework's `usePwaUpdate`).
- `pwa-plugin.ts` — hand-rolled service worker + manifest emission per deploy slot (the same pattern as the sibling contacts app); `src/app-pwa.ts` holds the cache-id contract both sides share.
- `src/identity.ts` — the single source for name, copy, palette, and URLs.
- `src/output-bridge.ts` — routes the engine's output module into the oss-framework log store.

The [oss-framework](https://github.com/niclaslindstedt/oss-framework) supplies the update-prompt state machine and UI (`pwa`), logging (`logging`), and the theme tokens its components style with; the runtime is Preact via `preact/compat` overrides.

## `tests/` and `scripts/`

Root-level vitest suites cover the generator's R-rules, the drift and jump moment by moment, the gearboxes, and full bot simulations (see [simulation.md](simulation.md)). `scripts/` holds Node tooling: the sim CLI, track previews, the audio audition page, headless screenshots, the icon/OG generator (pure-Node PNG encoder in `scripts/lib/png.mjs` — no native image deps), the SEO checker, and the release plumbing (`scripts/release/`, changeset fragments → CHANGELOG).

## Deployment

The app deploys to GitHub Pages at [game2.niclaslindstedt.se](https://game2.niclaslindstedt.se/) in three slots — `/` (latest release tag), `/preview/` (main), `/branch/` (parked feature branch) — via `pages.yml`; `release.yml` cuts versions from changeset fragments and chains the deploy. Details in [configuration.md](configuration.md); platform shells beyond the web in [platforms.md](platforms.md).
